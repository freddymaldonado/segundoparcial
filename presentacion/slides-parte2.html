Grupo 3 · Freddy Maldonado · Joaquin Peredo

El problema

Cuando la IA escribe el código,
¿quién lo audita?

Un solo prompt no basta: hace falta colaboración, validación y trazabilidad.

Convertimos el auditor en una arquitectura donde cada agente tiene un rol, conversa con los demás y nada llega al reporte sin pasar por el Validador y el humano.

Comunicación real · 4 roles mínimos + 1

5 agentes, 5 roles

📥
Recolección
Lee el código y extrae + verifica dependencias
🛡️
Seguridad
Busca vulnerabilidades, secretos y patrones peligrosos
📦
Dependencias
Detecta librerías riesgosas o inventadas (slopsquatting)
✅
Validador
Confirma si cada hallazgo es real o falso positivo
📝
Reporte
Prioriza riesgos y redacta para el analista humano

Seguridad y Dependencias corren en paralelo (asyncio) — más rápido y más realista.

Herramientas MCP funcionales · src/server.py

Tools del servidor

list_targets()
Lista archivos auditables + hash SHA-256
read_source()
Lee el código numerado — sin ejecutarlo
extraer_dependencias()
Detecta librerías declaradas
verificar_dependencias()
Clasifica: estándar / conocida / sospechosa
write_report() · write_html()
Persisten el reporte final
registrar_conversacion()
Guarda el diálogo entre agentes

Seguridad agregada a mano: _safe_resolve bloquea path traversal y no existe ninguna tool que ejecute código.

Uso de Vibe Coding

Construido con IA,
asegurado por nosotros

  • Prompts: "convertir el auditor en multi-agente sobre MCP", "protocolo de 7 campos", "back-and-forth Validador ↔ autor"
  • Errores corregidos: riesgo de path traversal → _safe_resolve; la IA inventaba paquetes → veredicto determinista de dependencias
  • Decisiones de seguridad: el servidor nunca ejecuta el código; validación humana obligatoria antes del reporte
